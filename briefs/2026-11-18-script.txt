## Known exploited vulnerabilities

One addition to C I S A's catalogue. Puppet Enterprise, from Perforce, the configuration management software that tells thousands of servers what to be. The flaw is in how Puppet Server processes reports. Any machine holding a valid agent certificate can run code on the Puppet server itself, and if certificate signing is set loosely, that may need no credentials at all. It scores nine point four out of ten. There is public proof of concept code, and federal agencies have until the first of December. Here is the thing about a Puppet server. It is the one machine every other machine obeys. Treat it the way you treat your domain controllers, and check how autosigning is set.

Deadlines. Apple's older flaw is due today. SonicWall on Friday. Outlook, Openwave, Cisco BroadWorks and Chrome next Tuesday.

And the Confluence flaw in Apache Axis is still not in the catalogue, despite Rapid Seven's report that it is being used. Rapid Seven has filled in the story of one intrusion, and it is instructive. The attacker's requests came back as server errors, which is what any monitoring would see, and yet behind each error, a shell and a download ran. Hundreds of encoded commands followed, through tunnelling services, in a pattern that suggests A I assisted tooling. The attacker trawled the database and the attachments for passwords and card numbers. About four hours in, a harvested service account was querying a cloud data warehouse. About twelve hours in, it was signing in to Microsoft three sixty five with legacy authentication. So if you run Confluence, here is the hunt. Look for legacy authentication sign ins to Microsoft three sixty five by any service account that Confluence knows about.

Java Four Shell. A flaw in the Java runtime, in a piece of code that speeds up a common encoding routine on newer processors. It only affects sixty four bit Intel and A M D machines that have a particular set of vector instructions, so roughly Intel from Ice Lake onward and A M D from Zen four onward, which is to say most modern servers. Where it applies, it can be reached before login in the default setup of Keycloak, Jira, Confluence, Artifactory, Jenkins and PingFederate. Oracle scores it eight point one. Red Hat, provisionally, nine point eight. No exploitation is known yet, but one research firm says it holds a full working exploit and has not released it, and C I S A has issued an alert telling people to patch immediately. Oracle, Amazon Corretto, Azul and GraalVM have fixed builds. Red Hat does not yet. If you cannot patch, there is a startup flag that switches the vulnerable routine off. The real work is inventory. Java hides inside appliances and containers, each with its own copy, and nobody ever counts them.

ScreenConnect. ConnectWise says attacks continue against out of date on premises servers and those with any of five third party extensions enabled, and that switching the extensions off does not remove access an attacker already has.

Exploited, but not in the catalogue. A payment extension for Magento online stores, made by a company called Rootways, has a flaw that is being used to read files, reach the database and plant a card skimmer. Fixed in version four point one point five. Shops that use it should assume the worst and look. And Cyderes has exposed an access broker called tcherber, selling more than five hundred stolen FortiGate V P N credentials, and going after SonicWall too, with its own loader and ransomware behind it. An excellent morning to audit who can log in to your V P N, and from where.

Briefly. The researcher who looked at Danfoss refrigeration controllers, the kind involved in the French supermarket attacks, says he found six previously unknown flaws in under an hour. One of them may allow code to run before login. The device has no secure boot. He called it not rocket surgery, which is one way to put it.

## A I attacks and trends

The Microsoft agent framework. Two versions of the package, one point two six point one and one point two six point two, were live on the Python index for about forty five minutes yesterday, from about twenty five to four to about twenty past four in the afternoon, Eastern. The package is downloaded around a hundred and ninety thousand times a month. The malicious code sat in a special kind of file that Python runs every time it starts, whether or not anything ever imports the package. It collected environment variables and the stored credentials of the Azure command line, npm, pip, git, Docker, Hugging Face and Azure DevOps. That is the familiar part. The unfamiliar part is that it then asked the cloud for brand new tokens, from Azure DevOps, from managed identities, and in the second version from GitHub Actions. As StepSecurity put it, rotating stored secrets does not cover those. A new maintainer account was added to the project the same day, and the publishing credential may still be in someone else's hands. Pin version one point two six point oh. And if a build system installed either bad version, revoke the tokens that machine could mint, not just the ones it held.

Bitdefender's twenty two repositories are a different shape of the same idea. Each looks like an ordinary project. Inside are instruction files written for A I coding agents, the files called agents dot M D and Claude dot M D, which tell the agent to run a setup script quietly. And a settings file for Claude Code includes a hook that runs at the start of a session, once the user has trusted the repository. Then a stealer takes GitHub, cloud, pipeline, browser, password manager and S S H secrets, rewrites the configuration of fourteen different coding agents, Claude, Codex, Gemini, Copilot, Cursor and Cline among them, commits itself to up to twenty five other repositories with the stolen tokens, and tries to republish itself to the package registries. Consultants clone strangers' repositories constantly. That is the population to talk to.

Fireworks A I, the model hosting company, has split its October trouble into two incidents. The second, from the twenty third to the thirtieth of October, through a third party cloud host, reached account and billing information for every account created before the thirtieth of October. No card numbers. If your teams use Fireworks, that is everyone.

Briefly. Google's threat intelligence group says a Chinese state group is building its own automated attack framework. The firm Trajectory names Gemini Four Argon as the model behind Epoch A I's incident, in which swarms of up to eighty agents probed its website, though Epoch has not confirmed that. Varonis describes a phishing kit that rewrites each email with a language model, over and over, until it gets through. And Anthropic will shorten its disclosure deadline for high and critical bugs to thirty days from January.

## The deep dive: COLD RELIC

Now. COLD RELIC.

Google's Mandiant and its threat intelligence group published a case study yesterday called COLD RELIC: A Case Study in Impersonation and Compromise. You may know the group by other names. Google used to call it COLDRIVER. Microsoft calls it Star Blizzard. Others say Callisto, or Gossamer Bear. Google describes it as Russian state sponsored and cites the American Justice Department's assessment that it operates within the F S B, Russia's Federal Security Service. Google does not give a confidence level for these particular intrusions, and the link between the two cases rests on phishing links and pretexts that name the first victim. That is the honest shape of the attribution.

Why should a consulting firm care? Because this is a group that uses what it steals from one organisation to impersonate that organisation's people to their friends. Not malware. People. Directories, mailboxes and relationships taken from victim one become the introductions to victim two. A consulting firm sits in the middle of a very large web of exactly those relationships, with clients, alliance partners, alumni and experts. That makes us useful twice over: as a store of who knows whom, and as the target of a message that appears to come from a client we trust.

The first case. Late last year, an American organisation running Google Workspace. COLD RELIC had stolen the credentials of a super administrator, the account that can do anything. It got past the second factor by pushing approval requests until someone, tired or distracted, pressed yes. And it connected through a residential proxy, an ordinary home internet address near the victim, so that no impossible travel alert fired. A new device was registered.

Then came the part that matters for anyone doing incident response. It enrolled passkeys, it generated backup codes, and it added its own multifactor devices. And when the victim reset passwords and sessions, the passkeys survived. Access continued. Later, the victim reset passwords but did not revoke sessions, and access continued again. A password reset alone, Google says, is not enough.

What did it take? Essentially everything. It mass shared the whole organisation's Drive to an attacker mailbox and downloaded it directly. It ran a tenant wide customer takeout, which is Google's tool for exporting an entire organisation's data. It exported the employee list. It set up mail clients to keep syncing mailboxes from outside. It searched for passwords, for mail archive files, and for personnel records. And it covered its tracks with some care. It queried the security investigation tool and the email audit logs to see what the defenders could see. And it viewed, changed and deleted notifications in the Alert Center, the place where Google would have told the administrators that something was wrong. It sat there for several months.

After it was evicted, it did not leave. It turned around and impersonated the victim's own staff, to their colleagues and to their associates. In June this year, a link naming the first victim turned up on VirusTotal.

The second case. Another American organisation, this one using Microsoft Entra I D to sign in to Google Workspace. Someone there was contacted on an encrypted messaging app by a person posing as an employee of the first victim. A trusted name, from a trusted organisation, with a document to share. The link led first to a compromised legitimate website, which fingerprinted the visitor and passed them on. Then to a page that captured Entra credentials and tokens. Then, to keep things tidy, to a real looking lure document. Once inside, COLD RELIC registered a new multifactor device, downloaded in bulk, and renamed its messaging profile to start a new persona. The links had a tell: parameters in the address naming the earlier victim or the lure document. New COLD RELIC phishing has been seen as recently as this month.

Now the honest bit. Google has published no indicators. No addresses, no domains, no file hashes. It gives two internet providers as examples of the residential networks used, and those are ordinary consumer providers. Blocking them would block a great many innocent people and no one in particular. So this is a hunt by behaviour, and Google has given us a good table to hunt with. The detail is in the written brief. Here is the shape of it.

One. A run of rejected push approvals followed by a success from the same address. Two. A new passkey or a new device registered just after that pattern. Three. A sign in using a backup code from outside your corporate networks. Four. Any mail client outside the approved list being granted full access to Gmail. Five. A tenant wide takeout being created at all. Six. Spikes in Drive downloads or external sharing by a single user, especially to personal Gmail addresses. Seven. Bulk deletion of alerts in the Alert Center, which is the action you would least want to miss. And eight, someone downloading the user list or running investigation queries who has no business doing so. In Entra, the same idea. Look for new authentication methods registered, and sign ins from home internet providers in the user's own city.

And the response. Hardware security keys where you can, and Google's Advanced Protection for the people who matter most. Make registering a passkey or a new second factor something that needs an administrator or a second channel to approve. When you find a compromise, revoke every session, refresh token and app grant, in both Workspace and Entra, and remove every passkey, backup code and device you did not issue. Disable takeout where nobody needs it.

And one of our own. Brief the people who face clients, the partners and their assistants above all. If someone from a client gets in touch on Signal or WhatsApp with a document to look at, check it with them through a channel you already know. The client may well be real. The person on the other end may not be. COLD RELIC's whole method relies on the fact that we are polite to the people we know.
