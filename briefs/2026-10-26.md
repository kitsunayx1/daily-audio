## 1. Top three things to know

1. **PHP2Shell has its first confirmed break-in, apparently run by an AI agent. KEV gained two entries due today.**
   - Unit 42 says attackers exploited PHP2Shell at a **European government entity**, planted a web shell, and had password hashes and MFA secrets within **two hours**. They then relayed NTLM into Active Directory and tried for Domain Admin (outcome not stated).
   - Unit 42 judges the operator was an **AI agent**: command batches wrapped in parse-friendly delimiters, short sequential tasks, quick pivots after failures. No attribution.
   - CYFIRMA reports suspected **Lazarus-linked** scanning (moderate confidence) of 216 unpatched PHP hosts in 12 locations.
   - **[CORRECTION to Friday's brief]:** CISA did add to KEV on 23 Oct, after our cut-off: **Collabora Online built-in CODE server (Nextcloud)** and **Arista VeloCloud Orchestrator**. Both federal deadlines are **today, 26 Oct**. PHP2Shell is still not in KEV.
   - **Action:** confirm every internet-facing PHP host and appliance is patched; set `session.upload_progress.enabled=0`; hunt from 17 Oct for shells spawned by PHP workers and NTLM from web servers. Patch or remove the Nextcloud built-in CODE server app.
2. **The law-firm run widens to White & Case and Weitz & Luxenberg. PwC confirms a vendor incident.**
   - **White & Case** listed by Qilin (25 Oct, no proof or volume). **Weitz & Luxenberg** listed by Falcon, claiming 82 GB including privileged communications and client medical and settlement data. **Sanders Law Group** listed by Rhysida (about 8 TB for sale). Three large US firms in five days, after Kirkland & Ellis on Thursday.
   - **PwC** told Reuters the incident was at a third-party vendor hosting employee learning records, with no client, sensitive personal or financial data, and no impact on its network. It would not comment on the 590 GB figure. The vendor is not named. Everest's countdown ends about **27 Oct**.
   - **[OLDER] Opportune LLP**, a Houston energy-sector advisory firm, filed a breach affecting **128,106 people** (Chaos ransomware claimed it in July).
   - **Action:** check White & Case, Weitz & Luxenberg, Sanders Law Group and Opportune in the vendor and client database. Expect PwC-themed recruitment and alumni phishing if data is published.
3. **Developer identity is the new perimeter: stolen GitHub tokens, hijacked coding agents.**
   - **Gheist** (Wiz): an automated campaign uses stolen GitHub tokens to push a workflow that prints every readable secret base32-encoded (bypassing log masking), downloads the log and deletes the run. **850+ accounts, 13,500+ branches**, including private enterprise repos and GitHub Enterprise Server. GitHub's hold on suspicious runs covers public repos only. Today's deep dive.
   - A malicious **AGENTS.md / CLAUDE.md dropped in the Downloads folder** hijacked AI coding agents in one real case (Forever Security). In testing, Codex ran the payload in over 90% of attempts; Claude Code was steered about half the time.
   - **LiteLLM's** root cause now traces to an Agent Platform master key leaked publicly on 27 May and never revoked.
   - **Action:** hunt for `ci-sync-*` branches and quickly deleted workflow runs; rotate CI secrets in any repo touched; block coding agents from running in `~/Downloads`.

Cortex Xpanse counts 22.6M+ exposed instances that may be vulnerable.
- **CYFIRMA (25 Oct):** 21 compromised nodes probed 216 unpatched hosts in the US, Japan, South Korea, Thailand, Indonesia, Australia, Taiwan, India, Singapore, the UAE, Saudi Arabia and the EU (government, finance, logistics, aviation, manufacturing), coordinated over I2P. - **Counterpoints:** CrowdStrike saw no successful exploitation and says most public PoCs only crash PHP. Sophos corrected an earlier report: its Potassium (Mirai) install attempt was blocked. VulnCheck has a private ASLR-bypass exploit.

ReliaQuest log signs: POST answered with HTTP 500, PHP memory-exhaustion or heap-corruption errors, Apache worker crashes. - **Fixed:** PHP 8.2.35, 8.3.36, 8.4.27, 8.5.12.

## 12. Threat actor deep dive: Gheist, stolen GitHub tokens used to drain CI/CD secrets (Wiz, 25 Oct)

### Summary
- An automated, unattributed campaign takes stolen GitHub tokens and pushes a workflow into every repository each token can write to. The workflow prints all readable secrets **base32-encoded**, so GitHub's log masking no longer recognises them. The tool downloads the log through the API and **deletes the run within seconds**. There is no attacker server: the data leaves through GitHub itself.
- **Scale:** 13,500+ planted branches, 850+ compromised accounts, including enterprise private repositories and GitHub Enterprise Server.
- GitHub's 28 Jul safeguard that holds suspicious runs for approval covers only **public** github.com repositories. In private repos and GHES the payloads ran.
- In one enterprise case, cloud credentials from the same organisation were used hours later to enumerate AWS Secrets Manager (source of those credentials not stated).
- **Attribution:** none. "Gheist" is the tool's user-agent string. Some victims were also infected with PolinRider, which researchers link to North Korea, and 57 accounts overlap with May's "Megalodon" campaign. Neither amounts to attribution.

### Timeline (2026)
- **Mar:** Trivy supply-chain compromise, a possible source of exposed tokens.
- **May:** Megalodon campaign; 57 of its victim accounts later appear in Gheist.
- **28 Jul:** GitHub starts holding suspicious runs, public repos only.
- **15 Sep:** Wiz starts tracking Gheist.
- **28 Sep:** a second tool variant appears, adding a six-minute timeout and a per-environment job matrix within hours.
- **6 Oct:** 391 accounts rename about 1,461 repositories to cracked-software lures.
- **18 Oct:** 25 Gheist accounts each create a "Windows RDP Runner" repository.
- **19 Oct:** base32 separator added, then a `sync-host` job aimed at self-hosted runners.
- **19–20 Oct:** three victims re-push Gheist commits carrying a PolinRider loader in `vite.config.js`.
- **24 Oct:** still active; about two-thirds of the accounts involved are gone from GitHub.
- **25 Oct:** Wiz publishes.

### Initial access
- Stolen GitHub tokens from infostealer logs and earlier supply-chain breaches (T1528, T1078). Any token with write access is enough, because a workflow can read every repository, organisation and environment secret available to that repo. In enterprise cases the tool cycled through several users and automation accounts within minutes and cloned private repositories first.

### Tooling
1. Create a branch matching `^ci-sync-[0-9a-z]{6}$`.
2. One unsigned commit, `ci: sync config`, adding only `.github/workflows/sync-check.yml`.
3. The workflow pipes `toJSON(secrets)` through `base32 -w 120`, one job per deployment environment, so environment-scoped (often production) secrets are exposed.
4. Download the log; delete the run.
5. A `sync-host` job on self-hosted runners writes `.gdmp_pat`, `.gdmp_patg`, `.gdmp_sweep`, logs stages as `===== gdmp-pivot: <stage> =====`, and searches for 31 token formats, private keys, `.env` files, Terraform state, shell history, the Docker socket and cloud metadata. Wiz says this job is buggy and has not been seen succeeding.

### Persistence
- Little true persistence: planted branches remain and leaked secrets stay valid until rotated. The PolinRider loader in `vite.config.js` is the only lasting implant reported. **Deleting branches or runs does not undo the exposure.**

### IOCs (no IPs or domains published)
- User agent `gheist`; branch `^ci-sync-[0-9a-z]{6}$`; commit message `ci: sync config`; file `.github/workflows/sync-check.yml`
- Strings: `toJSON(secrets) }}' | base32 -w 120`, `===== gdmp-pivot:`
- Files: `.gdmp_pat`, `.gdmp_patg`, `.gdmp_sweep`
- Workflow Git blob SHAs: f3da2b8b357dcda02fd455d314be2a95007516a6, d09535857a741bbb976bdc084a9a021713133291, 1dc5af9cce950aad1eb1546ecce8565b117540c4, c665b778b2d822453293003e7ca0bbb2cb08e39d
- Not to be confused with GhostAction, a separate campaign (193.32.204[.]199).

### Hunting
1. **GitHub audit log** (org, enterprise, GHES): workflow runs on `ci-sync-*` branches deleted within about 60 seconds of finishing; any API call with user agent `gheist`; one token touching many repositories within minutes; `git.clone` bursts by automation accounts.
2. **Repositories:** enumerate `ci-sync-*` branches and commits that add only `sync-check.yml`.
3. **Cloud:** CloudTrail `AssumeRoleWithWebIdentity` (or Azure/GCP federated token exchange) whose subject contains `ref:refs/heads/ci-sync-`; `secretsmanager:ListSecrets` / `GetSecretValue` bursts from CI roles.
4. **Self-hosted runners:** `.gdmp_*` files and `gdmp-pivot` in job logs.
5. **Endpoints:** check the devices of token owners for infostealers.

### Response
1. Rotate every repository, organisation and environment secret available to any affected repository.
2. Revoke the tokens that pushed the commits; reimage owners' devices if an infostealer is found.
3. Treat any self-hosted runner that ran a `ci-sync` branch, and its instance role, as compromised.
4. Never approve held `sync-check` runs.
5. Harden: required reviewers on production environments; OIDC trust limited to protected branches or environments; GitHub Apps or short-lived fine-grained tokens instead of PATs; ephemeral runners without the Docker socket and with metadata blocked; enterprise policy restricting which actions and workflows may run.
