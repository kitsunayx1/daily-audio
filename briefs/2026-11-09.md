### OpenSSH "SSHole" CVE-2026-123158: exploited [UPDATE]
- Previdian's Alpine honeypot was rooted less than 9 hours after publication (first source 89.116.89[.]18); by 8 Nov, 20 attempts from 13 IPs in nine countries. CVSS 8.1; musl systems without PAM, accounts with "*" password hash; fixed 10.6p2. Not in KEV. Hunt "Accepted password for" on alpine, root or key-only accounts; review doas use, new users, authorized_keys.
- Sources: https://thehackernews.com/2026/11/hackers-exploited-openssh-sshole-flaw.html ; https://www.securityweek.com/openssh-rushes-patches-for-sshole-authentication-bypass/

### WordPress CVE-2026-119977: the fix update has its own window [UPDATE] [CONFLICT]
- The update installing 7.1.4 still runs the old updater; on 5.9+ it uses a predictable wp-content/upgrade folder, so an attacker can race it. Wordfence saw attempts 9 minutes after deploying its rule; two sources watched small site sets for about 14.5 hours, apparently waiting for updates. Unverified public exploit code exists.
- Mitigation: block /wp-content/upgrade/ at the web server before updating and confirm 403; do not rely on .htaccess in that folder; WP-CLI is not a safe alternative. CVSS conflict: 8.1 (Wordfence), "low" (WordPress), 9.5 (CVE Brief).
- Source: https://thehackernews.com/2026/11/installing-fix-for-exploited-wordpress.html

### QNAP NAS breached via Plex2Shell [NEW]
- QNAP has customer reports of compromise through Plex Media Server flaws (KEV since 20 Oct). Fix PMS 1.43.3.10861+; updating does not remove payloads. If exposed, reinstall QTS / QuTS hero, reset credentials, close port 32400. https://bleepingcomputer.com/news/security/qnap-says-hackers-breaching-nas-devices-in-plex2shell-attacks

## 12. Deep dive: Storm-2603's fileless SharePoint intrusion and attempted Warlock deployment (Kaspersky, 5 Nov) [OLDER]

**Why it matters:** on-prem SharePoint is core document infrastructure for consulting and law firms. Storm-2603, a ransomware actor (Warlock, earlier LockBit), keeps using the 2025 ToolShell n-days. The implant lives only in memory inside w3wp.exe, so patching alone or IOC-only hunting misses it. It abuses legitimate DFIR and remote-access tools.

### Sources
- https://securelist.com/storm-2603-fileless-toolshell-attack/121467/ (Alexander Rodchenko, Rodrigo Wanderson; published 5 Nov 2026, the day before the window)

### Attribution and confidence
- Kaspersky: Storm-2603, **moderate confidence**, on ToolShell exploitation and post-exploitation matching other documented cases. Storm-2603 is Microsoft's name. Victim sector and region not disclosed.
- The intrusion ran 20–26 December; the article gives no year (presumably 2025).

### Timeline
- 20 Dec: one ToolPane probe for CVE-2025-53770 (apparently from ONYPHE infrastructure); about 12 minutes later, a connection from bulletproof hosting (Pfcloud UG).
- 21–23 Dec: quiet. 24 Dec: full RCE chain via w3wp.exe from 45.91.94[.]204; webshell loaded into the ASP.NET runtime; w3wp.exe spawns msiexec.exe to install a remote Velociraptor MSI.
- 26 Dec: discovered. The 20 Dec probe had been triaged as low priority.

### Initial access
- CVE-2025-53770 and CVE-2025-53771 (ToolShell) via crafted HTTP requests to on-prem SharePoint; BuildManager manipulation to bypass precompiled-application checks (T1553).

### Tooling
- In-memory C# framework "vskp2" (modules FileDownloader, LoggedOnUsers, ProcessList, NetworkInfo, MSI, User); suo5 tunnelling; EfsrTiny (from EfsPotato) to SYSTEM; SAMRPCNative to create accounts.
- Velociraptor 0.73.4.0 (itself vulnerable to CVE-2025-6264); Zoho Assist Unattended; VS Code CLI / Insiders tunnels; Cloudflare Tunnel.
- EDR killing via vulnerable driver rsndispot.sys plus a sideloaded Warlock AV-killer DLL. Warlock ransomware blocked by Kaspersky.
