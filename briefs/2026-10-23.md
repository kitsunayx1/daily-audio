## 1. Top three things to know

1. **A Big Four firm is on a leak site: Everest claims PwC. And the law-firm run continues with Kirkland & Ellis.**
   - Everest lists **PwC** (country given as GB) and claims 590.69 GB and 108,426 files from internal HR and learning systems: employee and training records, "audit methods", confidential documents, a client and engagement tracker, and SSO source code and configuration.
   - A directory named `pwc-stg.csod.com` points to a **Cornerstone OnDemand staging tenant**, which would mean a third-party SaaS route. Unconfirmed. PwC has not commented; a reported 28 Oct release date is unconfirmed. CyPro notes Everest has listed fabricated victims before.
   - Silent Ransom Group lists **Kirkland & Ellis** and two more redacted names. Bravox lists **Barrow & Grimm**. **Lexitas**, the court-reporting and litigation-support vendor used by many law firms, filed a breach notice in Vermont.
   - **Action:** review HR and learning SaaS tenants, **including staging and test tenants**, and any SSO configuration they hold. Expect PwC-themed phishing aimed at its staff and clients.
2. **Someone is harvesting AI keys from the platforms developers deploy on.**
   - **Railway**, a cloud app-hosting platform with about 4.8M users, says an intruder accessed customer environment variables, some decrypted. Railway believes it is part of a series of attacks on platform companies "with the aim of compromising AI inference providers". Zeabur, OpenCode Console and LiteLLM fit the same pattern.
   - **LiteLLM's root cause:** GitHub tokens that passed through an internal LiteLLM deployment were captured in its logs, and an attacker who reached that deployment used them to take over the release pipeline.
   - **Action:** rotate secrets stored on PaaS platforms, and watch AI-provider billing for unexpected models or spikes. Treat AI gateway logs as sensitive.
3. **PHP2Shell is now millions of attempts and a botnet, and an SD-WAN zero-day is exploited.**
   - Cloudflare counts **millions** of PHP2Shell attempts, and a Mirai variant called "Potassium" is using it. Amazon saw a first attempt on **17 Oct**, four days before disclosure. Still no confirmed successful compromise, but VulnCheck has shown a working chain on production settings.
   - **Arista VeloCloud Orchestrator CVE-2026-114625** (SQL injection, CVSS 9.9) is exploited. Any logged-in user can become an operator.
   - **Action:** patch PHP everywhere, including appliances (QNAP, cPanel, Okta Access Gateway have fixes). Patch on-prem VeloCloud Orchestrators.

## 2. Breaches and incidents

### Railway: customer secrets accessed
- **What happened:** Railway detected "anomalous activity" on systems storing customer environment variables. An unauthorised party may have accessed encrypted variables, and for some users obtained the decrypted contents: API keys, database and registry credentials. Railway says a "subset" of users was affected; no count.
- **Railway's assessment:** likely part of a series of attacks on platform companies aimed at compromising AI inference providers. It notified upstream providers to revoke keys.
- **Response:** paused deployments, rotated bucket keys, invalidated API tokens, reset GitHub tokens, and published GCP and AWS hunting guidance. Builds were back for Pro and Enterprise at 08:44 UTC on 22 Oct.
- **IOC:** researcher Taylor Monahan linked crypto thefts to Ethereum address 0xd9773325282874d18cb83f1fe50f14c39750b2ee.
- **Action:** if the firm or a vendor deploys on Railway, rotate every stored variable.

## 5. Software supply chain

### LiteLLM [UPDATE]: root cause
- LiteLLM's account: an internet-exposed internal LiteLLM deployment logged response bodies in which Claude Code had embedded users' GitHub CLI OAuth tokens. An attacker reached that deployment through an "innocuously named user account", possibly via a recently patched flaw, and collected the tokens.
- With three developer tokens and an org-owner token, the attacker disabled branch protection, force-pushed, and pointed the release workflow at the lookalike repo `Berri-AI/litellm`, so poisoned artifacts were signed and published.
- Wiz saw AWS instance-role credentials from CI runners and Kubernetes nodes validated about 4.5 hours after theft, consistent with "LLMjacking" (stealing access to paid AI models).
- Fixes: releases moved to a private repo, Docker tags made immutable, images signed. Enterprise private-registry users unaffected.
- **New IOCs:** credential-validation IPs 168.100.8[.]57 and 165.227.201[.]8 (21 Oct 16:20–17:01 UTC).
- **Lesson:** an AI gateway's logs can capture every token that passes through it.

## 6. AI attacks, breaches and trends

### Platforms as a route to AI keys
- Railway's statement, plus Zeabur (3.2M environment variables), OpenCode Console keys, LiteLLM and an unconfirmed OpenRouter claim, point to a campaign aimed at stealing AI inference access.
- **Action:** watch AI-provider usage and billing for unexpected models or spikes; set spending caps; rotate keys held on third-party platforms.

### OpenCode: malicious MCP server can run code at sign-in
- A malicious or hijacked MCP server can execute code during `opencode mcp auth` on Windows and WSL, versions 1.0.137 to 1.18.32. Fixed in 1.18.33. No CVE; no exploitation.
- https://thehackernews.com/2026/10/opencode-flaw-lets-malicious-mcp.html
- https://www.pillar.security/blog/open-and-shut-remote-code-execution-in-opencode-via-mcp-oauth

### ChatGPT GitHub connector prompt injection
- A hidden prompt in a public repo makes ChatGPT write a GitHub Actions workflow into a private repo the connector can reach; the workflow exfiltrates secrets. OpenAI ruled it out of scope.
- https://sunilawesome.in/chatgpt-github-connector-vulnerability
- https://thehackernews.com/2026/10/threatsday-ai-secrets-leak-pingcap.html

## 12. Threat actor deep dive: the Microsoft 365 "token spraying" campaign (Huntress, 22 Oct)

### Summary
- Huntress tracked an unattributed operator that phished Microsoft 365 users with adversary-in-the-middle (AiTM) relays and device-code lures, then **replayed the stolen post-MFA tokens at scale** from 1337 Services GmbH (AS210558, Hamburg). Huntress calls it "token spraying": password spraying, but with stolen sessions.
- **14 Jul to 22 Sep 2026, 79 organisations:** 497+ successful sign-ins and 200,000+ failed attempts from 193.26.115.0/24; 48+ rogue Entra devices registered; MFA methods wiped and replaced in 19 organisations; hidden inbox rules used for payroll and invoice fraud.
- Entra ID Protection flagged some replay IPs as linked to "nation state actors or cyber crime groups". No attribution.
- **Why it matters:** the persistence (a rogue authenticator and a registered device) survives a password reset, and the fraud targets payroll and the firm's accountants.

### Timeline
- **14 Jul to 3 Aug:** 37 organisations, 37 rogue devices. In one case the session was hijacked 12 minutes after the MFA prompt, and an authenticator added about 50 minutes later.
- **From 17 Aug:** device-code phishing added, MFA wiping, more hidden rules.
- **11 Sep:** automated replay burst using a `node` client: 303 successful sign-ins across 29 organisations over four days (Huntress gives 232 across 28 elsewhere).
- **2–22 Sep:** relay and replay paired; one takeover replayed the session about 4 minutes after capture.

### Access
- AiTM phishing relays capture the session after MFA (T1557, T1566.002).
- Device-code phishing: victims type attacker-generated codes into the genuine Microsoft sign-in page.

### Replay tooling
- **Scripted:** user agent `node` or bare `Mozilla/5.0`; request types `OAuth2:Token` and `Cmsi:Cmsi`; clients Microsoft Office `d3590ed6-52b3-4102-aeff-aad2292ab01c` and Microsoft Authentication Broker `29d9ed98-a469-4536-ade2-f981bc1d605e`; resources Graph, Exchange Online, SharePoint and the Device Registration Service (`01cb2876-7ebd-4aa4-9cc9-d28bd4d359a9`).
- **Browser:** current Chrome or Edge on Windows; `Login:reprocess` and `OAuth2:Authorize`; client OfficeHome `4765445b-32c6-49b0-83e6-1d93765276ca`.
- Post-compromise access through ExpressVPN, NordVPN, CrownCloud, DataWagon, GLOBALTELEHOST, LeaseWeb, Dynu and Interserver, and an RDP tunnel.

### Persistence
- **Rogue Entra-joined devices (T1098.005):** at least 48, named `DESKTOP-` plus exactly 8 uppercase hex characters (e.g. DESKTOP-54521F46, DESKTOP-BAF88EF4, DESKTOP-CA85907C). Windows' own default is 7 alphanumeric characters.
- **MFA tampering (T1556.006):** existing methods wiped and a new authenticator labelled **"iPhone 13"** registered within 3 hours.
- **Hidden inbox rules (T1564.008):** names such as `.`, `sss`, `ss`, `iT`, `,.`, `........`, `s`, `d`. Mail moved to RSS Feeds, RSS Subscriptions or Conversation History and marked read.
  - Rule `s` hid payroll, direct deposit, bank and bonus mail.
  - Rule `d` hid one external CPA's mail. A payroll-change email went to that CPA; the `d` rule was created five minutes after the `s` rule.
- A lookalike domain of a business partner was registered; one mailbox sent mass spam.

### IOCs
- **Replay hosts (AS210558):** 193.26.115[.]221, 193.26.115[.]199, 193.26.115[.]16, 193.26.115[.]21, 193.26.115[.]72, 193.26.115[.]210
- **Other 1337 Services addresses:** 124.198.132[.]33, 45.83.31[.]44, 192.159.99[.]172
- **AiTM relays:** 185.238.2[.]195; 2400:8d60:2::1:841d:5dd
- **Mail-rule host:** 167.148.41[.]96
- **Authenticator:** label "iPhone 13"; device token apns2-d8a3fedb1a3cd1287ca47c6851a49e6052ab6116b43666e674765ca892d798ce
- **Error codes:** `AADSTS53003` (blocked by Conditional Access) means the credential was valid, so treat it as a hit. `AADSTS50133` appeared on failed reuse.

### Hunting
1. Entra sign-ins: `OAuth2:Token` or `Cmsi:Cmsi` from hosting or VPN ASNs using the Office or Authentication Broker client with a `node` or bare `Mozilla/5.0` user agent, especially to Exchange or the Device Registration Service. Block or alert on AS210558 and 193.26.115.0/24.
2. Device registrations matching `^(DESKTOP-|Device-|Work Pc)[0-9A-F]{8}$` from hosting IPs. Confirm before deleting.
3. MFA methods deleted and a new one registered within minutes; unknown "iPhone 13" authenticators.
4. Inbox rules with 1–3 character or punctuation-only names, rules moving mail to RSS or Conversation History, rules on payroll or banking terms, or rules created by REST API from VPN or hosting IPs.
5. Device-code sign-ins by users with no reason to use device code.
6. Prioritise users by valid-credential signals such as 53003 blocks, not by raw spray volume.

### Response
- Revoke sessions **and** reset the password (a reset alone leaves the access token valid for about 90 minutes). Remove rogue devices, unknown MFA methods and hidden rules. Check for new app consents.
- Call payroll, accountants and partners to check for fraudulent payment-change requests.
- Conditional Access: MFA for all users, apps and client types without exceptions; block device-code flow with authentication-flow policies; restrict user app consent. Phishing-resistant MFA and token protection would blunt AiTM replay (our addition; not a Huntress recommendation).
