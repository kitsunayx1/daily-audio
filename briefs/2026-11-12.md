## 1. Top three

1. **ScreenConnect turned into a worm against MSP estates [NEW].** From about 17:47 UTC 11 Nov, an operator used ScreenConnect Run Command to push rogue clients and the "SCKit"/RelayTrap toolkit to at least 288 endpoints at 48 organisations within about 90 minutes. The kit is built to steal technicians' session cookies and jump to every panel they can reach. ConnectWise disabled five third-party extensions in about 400 partner environments; no ScreenConnect vulnerability found; no actor named. Ask your MSPs today (sections 4, 10, 12).
2. **N-able Hotfix 2 is not enough [UPDATE].** Huntress (06:10 UTC 12 Nov) says even fully patched N-central 2026.4 HF2 servers should be treated as vulnerable to new exploit code ("4EverAble2Shell", "Agent2Shell") published 11 Nov. No fix, no CVEs, no confirmed exploitation; scanning seen (section 10).
3. **Consulting in the frame.** Unit 42 tracked a coordinated campaign using the ARTEX AI pentest framework against cloud tenants in sectors **including retail and consulting**, abusing password-reset pages and exposed APIs rather than software flaws. Baker Tilly told clients their SSNs were taken through a third-party platform (10,456 Texans). Barracuda's KEV deadline is **tomorrow, 13 Nov** (sections 4, 5, 7).

## 5. AI attacks and trends

- **Unit 42: ARTEX in real intrusions, including against consulting [NEW]:** Managed Threat Hunting tracked a coordinated ARTEX campaign against customer cloud environments in sectors including **retail and consulting**. Attackers turned public password-reset pages and exposed APIs into cloud access, sometimes in under a day, with no software flaw. One pattern: more than 200 client secrets validated in about three minutes. As of October, 1,323 internet-facing hosts ran CyberStrikeAI, 609 ran ARTEX, 21 both. Advice: remove exposed OpenAPI specs, source maps and token-bearing configs; rate-limit reset and registration endpoints; block local passwords on federated accounts; hunt for first use of a cloud key from a new IP. https://unit42.paloaltonetworks.com/artex-and-ai-powered-red-teaming-tools/

## 12. Deep dive: ScreenConnect "SCKit" / RelayTrap, a worm built for MSP estates (Huntress, Sophos, ConnectWise; 11–12 Nov 2026) [NEW]

### Sources
- https://www.huntress.com/blog/sckit-worm-rogue-screenconnect
- https://www.sophos.com/en-us/blog/malicious-screenconnect-deployments-observed (undated page)
- https://thehackernews.com/2026/11/screenconnect-attacks-target-at-least.html
- https://www.connectwise.com/company/trust/advisories

### Why it matters
Consultancies and law firms often rely on MSPs or internal IT that run ScreenConnect. This campaign makes the remote-support tool the distribution channel and is designed to move from managed endpoints to the technicians who support them, and from there to every panel those technicians can reach (trusted relationship).

### Attribution and confidence
- No actor named by Huntress, Sophos or ConnectWise.
- Attacker ScreenConnect participant name "Addmin"; installer URLs carry `&c=Exploited<N> Actor Name: Addmin`.
- Huntress: RelayTrap C# source "appears to have been generated by an LLM" (detailed comments and references).
- MSP tags start partway through a sequential numbering scheme, suggesting earlier, unseen compromises.

### Timeline (UTC)
- Sept 2026: Huntress handled similar worm-like activity; ConnectWise later patched CVE-2026-84869 (CVSS 9.9, file transfer).
- 11 Nov about 17:47: first operator-driven Run Command activity (as SYSTEM) on cloud-hosted panels.
- About 10 minutes later: about one third of the 288 hosts hit. About 90 minutes after first detection: all 288 across 48 organisations.
- 22:45: ConnectWise advisory.
- 12 Nov: ConnectWise disables five third-party extensions in about 400 partner environments as a precaution; installation does not mean compromise.
- Versions seen: ScreenConnect 26.6.6.9747 and 26.7.6.9783.

### Initial access
Unconfirmed. Huntress saw no new vulnerability; telemetry points to compromised credentials or hijacked operator sessions. ConnectWise found no compromise of its own infrastructure and suspects third-party extensions that expose a remote-command API protected by a partner-set passphrase: **Labtech Plus, RMM Plus, RMM+, RMM Plus Password Link, RMM+ Password Link**.

### Attack chain (Huntress, Sophos)
1. Run Command checks for an existing client, then downloads and silently installs an attacker installer (Sophos: curl.exe to `C:\Windows\TEMP\sc.msi`, then silent msiexec).
2. Base64 batch dropper `sckit-run.bat` sends the Windows machine UUID to attacker infrastructure, which returns a per-host key, IV and salt; the kit decrypts into `%TEMP%`.
3. `sckit-loader.ps1` and host-specific `k<32hex>.ps1` extract the kit to `C:\ProgramData\RelayTrap`.
4. Install scripts add Defender exclusions and SRP/AppLocker rules blocking files pushed through ScreenConnect temp folders (locking out defenders), and install a second rogue client.
5. `TrapWatch.ps1` compiles `RelayTrap.cs` on host, creates scheduled task **TrapWatch** (SYSTEM, every 10 seconds), and stops the legitimate ScreenConnect service and sets it to manual.
6. `Panel-Lateral.ps1` attempted console takeover; failed on every recovered host log checked so far.
7. Designed, not observed end-to-end: when a technician connects, the kit steals their `.aspxauth` cookie (sqlite3.exe reads browser cookie stores), replays it to enumerate sessions, and uses `ToolboxRelayUploader.exe` (32-bit .NET) to upload a payload to the panel's Shared Toolbox, which runs as SYSTEM on reachable endpoints and is deleted after about 60 seconds.

### Artefacts (as published)
- `C:\Windows\Temp\sckit-run.bat`, `sckit-decoder.ps1`; `%TEMP%\sckit-loader.ps1`, `%TEMP%\k<32hex>.ps1`

### Hunting
- Review ScreenConnect Run Command history, Shared Toolbox history and instance audit logs, even with no alerts, and look back before 11 Nov.
- Look for: a second unapproved ScreenConnect client; curl or PowerShell pulling ScreenConnect MSIs into Windows Temp then silent msiexec; the TrapWatch task, RelayTrapLiteAlert Run value and `C:\ProgramData\RelayTrap\`; new Defender exclusions; the legitimate ScreenConnect service stopped or set to manual.
- Lite-Alert.ps1 watches ScreenConnect "file run" events (Event ID 201) and new ScreenConnect client services.
- Check for the five suspect extensions; watch for unusual panel sign-ins, new admin accounts and unexpected MFA prompts.

### Response (Huntress)
- Do **not** connect to suspect hosts through ScreenConnect; use EDR live response or WinRM.
- Treat any technician workstation that connected to a suspect host as exposed; investigate from a clean device.
- Keep hosts isolated until cleanup is complete (reinfection seen after isolation lifted).
- Remove the rogue client service, persistence and toolkit files; verify the legitimate client first.
- Terminate ScreenConnect web sessions, rotate ScreenConnect credentials, revoke browser and IdP sessions.
- Ask MSPs whether they run ScreenConnect with these extensions.
