## 12. Deep dive: Microsoft, "Threat actors use agentic AI tooling to find and abuse exposed secrets" (5 Nov)

**Why it matters:** autonomous ARTEX agents search public GitHub for a target's leaked OAuth and app secrets and turn them into Entra ID, Azure, M365, Azure DevOps and Azure AI access. Some victims were reached through a vendor-owned multitenant app used against several downstream tenants. In one case an agent went from GitHub search to exfiltrating Azure Key Vault data in about five minutes. A firm with many client tenants, vendor apps and code repositories is the natural shape of a target.

### Sources
- https://www.microsoft.com/en-us/security/blog/2026/11/05/threat-actors-use-agentic-ai-tooling-to-find-and-abuse-exposed-secrets/
- Corroboration: https://www.todyl.com/blog/stolen-app-credentials-real-access-an-actor-is-signing-into-entra-id-and-azure-devops-as-your-workloads (via THN; not read directly)
- https://thehackernews.com/2026/11/threatsday-apache-ofbiz-rce-dreamhost.html

### Attribution and confidence
- None. Microsoft calls the ARTEX network indicators "unattributed". It links a 21 Oct post on Storm-0940's ARTEX use in a ConnectWise supply-chain compromise but does not attribute this activity to Storm-0940.

### Timeline
- Aug 2026: agentic GitHub secret-search queries first seen. 28 Oct: earliest successful service-principal sign-ins from 199.19.77[.]84. 5 Nov 23:46 UTC: published.

### Initial access
- Valid leaked application credentials (including OAuth client secrets) in public GitHub config files and scripts, found by searches combining the target's name with secret, cloud-service or AI-provider keywords.

### Tooling and behaviour
- ARTEX chaining Nmap, curl, wget, Python HTTP clients, a WebFetch SDK and Playwright headless Chromium; adaptive retries; Azure Run Command; Microsoft Graph searches.
- Harvested storage keys, App Service settings, connection strings, publishing credentials, AKS credentials, AI/ML connections, AI-provider API keys and OAuth apps with Foundry access; enumerated and exfiltrated Key Vault secrets; accessed Storage and Azure DevOps.
- Todyl: at least 27 organisations reached via MSPs, 81 files downloaded, about 2,279 mailbox items accessed, from 199.19.77[.]84.

|---|---|

- No domains, hashes, app IDs or user agents published.

### Hunting (Microsoft-provided, condensed)
1. EntraIdSpnSignInEvents, GraphAPIAuditEvents and CloudAppEvents since 28 Oct for the IPs (Microsoft's first query omits .18; add it).
2. CloudAuditEvents and CloudStorageAggregatedEvents with SuccessfulOperationsCount > 0 for 199.19.77.84 and 65.87.223.26.
3. AADSTS7000215 / AADSTS7000222 errors mean someone holds a credential; a failure followed by success is urgent.
4. One IP authenticating to three or more service principals; one app requesting tokens across ARM, Key Vault, Storage and Graph in a short window.
5. Azure DevOps: PAT creation and first use, federated service connections, pipeline edits, unfamiliar user agents.
- Analyst-added (not Microsoft): scan the firm's public GitHub organisations for secrets mentioning the firm's name; inventory consented multitenant vendor apps per tenant; alert on Key Vault secret listing by service principals from non-corporate IPs.

### Response (Microsoft)
- Block the exact IP (not the ASN) for workload identities in Conditional Access; revoke sessions, PATs and SSH keys; remove all secrets, certificates and federated credentials on affected apps (including attacker-added ones; issued tokens stay valid until expiry); rotate Key Vault secrets; move to managed identities; enable push protection; MSPs review Partner Center and GDAP; consider decoys and tarpits.

### MITRE ATT&CK
- Not published; Microsoft lists only tactics (Initial Access, Discovery, Credential Access, Command and Control).
