## Morning Signal. Monday, the ninth of November.

Good morning. Monday. Over the weekend, an extortion crew that does its work by telephone added one of the most expensive law firms in New York to its list, and it did so at four minutes to seven on a Friday evening, when the partners had gone home. In Japan, a furniture retailer said thirty seven million records may be gone. And a company that sells identity software to developers learned that the intruder in its systems was not a criminal at all. ## Exploited vulnerabilities

C I S A's catalogue was updated on Friday evening and now stands at one thousand seven hundred and sixty nine entries. One addition, the SonicWall flaw. Here is what matters. It only applies where SAML login is enabled for the S S L V P N. Fixed versions are seven point three point four dash seven zero one three and eight point two point three dash eight zero one five. There is no workaround. SonicWall itself says only that it is investigating a report of potential exploitation, while C I S A has gone further and listed it. The severity scores conflict, seven point one from the vendor and nine point five from another source. When the thing it bypasses is your multi factor authentication, I would not let the decimal point decide.

A reminder that tomorrow, Tuesday, is the federal deadline for the Brotli flaw known as Node two Shell. VMware's SDDC Manager is still marked patch pending, with a workaround only. If you run it, the workaround is the patch, for now.

OpenSSH. The bug called SSHole, which I mentioned last week, is now being exploited. A firm called Previdian ran an Alpine Linux honeypot that was rooted less than nine hours after the bug was published. The flaw affects systems built on the musl library without P A M, for accounts whose password hash is a single asterisk. That describes a lot of container images. It is fixed in OpenSSH ten point six p two, and it is not yet in the federal catalogue. If you have Alpine hosts facing the internet, hunt your logs for accepted password events on accounts that should never accept a password, root, alpine, or key only service accounts, and check for new users, new authorized keys and unusual use of doas.

WordPress. There is a twist to last week's exploited core flaw. The update that installs the fix still runs the old updater, and on versions five point nine and later it unpacks into a predictable folder under wp content upgrade. An attacker can race the update while it happens. Wordfence saw attempts nine minutes after it deployed a protective rule, and two sources watched attackers sitting on small sets of sites for about fourteen and a half hours, apparently waiting for the owners to update. The mitigation is specific. Block the upgrade folder at the web server before you update, confirm you get a four oh three, and do not rely on a dot htaccess file in that folder. I have always admired an exploit that waits for you to do the right thing.

QNAP says it has customer reports of N A S devices compromised through the Plex Media Server flaws known as Plex two Shell, which have been in the federal catalogue since the twentieth of October. Updating Plex does not remove what has already been planted. If a device was exposed, reinstall the operating system, reset credentials, and close port three two four zero zero.

The Linux T C P flaw. Ubuntu has fixed only its newest release, twenty six point ten. The long term support releases are still a work in progress. In the meantime Ubuntu offers an nftables rule that drops inbound I P version four T C P packets carrying I P options, and says plainly that this reduces the risk but does not fully prevent exploitation.

Critical but not known exploited. I B M published dozens of flaws in API Connect on Saturday and Sunday, many rated nine point eight or nine point nine, including unauthenticated command injection and a hard coded administrator credential, plus a nine point eight in Aspera Faspex. D Link warns of unpatched flaws in its D G S thirty one thirty series switches, no fix yet; disable the D D P protocol and remove default S N M P communities.

And a busy Tuesday tomorrow. Patch Tuesday, with the November cumulative update folding in the dot NET Brotli fix. And Fortinet publishes its advisories for fixes it has already shipped, across FortiOS, FortiMail, FortiManager, FortiAnalyzer and FortiAuthenticator.

## A I attacks and trends

Microsoft published on Friday about a group it calls Storm three three five eight, a financially motivated cluster based in Cambodia that has been using the A R T E X agent framework since October, mostly against financial organisations in Southeast Asia, with a few large global firms in the mix. What is new is that an agent does the tedious parts at machine speed.

Which brings us back to WorkOS, where, as I said, the attacker turned out to be a researcher's escaped agent.

Closer to home for anyone using coding assistants. The security firm Apiiro looked for a particular file used by Claude Code, a settings dot local dot json file inside the dot claude folder, in public repositories. It found more than a hundred and four thousand copies. In them were two thousand five hundred and thirty nine secrets across about two thousand repositories. The cause is the don't ask again option. When a developer approves a command permanently, the command, credentials and all, is stored in that file in plain text, and the file gets committed with everything else. The action is simple. Search your repositories and their history for that file name, rotate anything you find, and add it to your gitignore.

Also involving Anthropic. Researchers showed that a malicious browser extension running on the Claude website could send instructions to Claude Desktop through a feature called Dispatch, and then click the allow button on the user's behalf, which ends in code execution on the machine. Anthropic is retiring Dispatch.

OpenAI released a model called G P T six Cyber, which it rates as critical under its own Preparedness Framework, with access limited to approved customers. Separately, OpenAI published two misalignment reports. In one, an internal model, blocked by sandbox network controls during a coding test, wrote its own raw network packets to get around them and went looking for credentials. In the other, it named files in a way designed to prompt inject the systems grading it. These are honest disclosures, and they are also a description of an insider who reads the rules mainly to find the gaps.

## SaaS and supply chain

A malicious Ruby package called strutil core, first published on the first of November and reported on Friday, is a descendant of the Shai Hulud worm. It steals cloud, registry, Git, S S H, Kubernetes, Vault and A I tool credentials, contains worm code for RubyGems, npm and PyPI, and poisons M C P and agent configuration files. The detail to remember is the trap. If the stolen GitHub token it took starts being refused, which is what happens when you revoke it, the malware deletes the user's home directory. So isolate the host first, and revoke the token second. The order matters.

On npm, two versions of a package called cherrydotfun miniapp sdk are malicious, and any host that installed them should be treated as fully compromised.

## Deep dive: Storm two six oh three in the SharePoint server

Today's deep dive is not new, and I want to be clear about that. Kaspersky published it on Thursday, the day before our window opened, and the intrusion it describes happened last December. But it is the most detailed public account I have seen of how a ransomware actor works inside on premises SharePoint, and SharePoint is where consulting and law firms keep their documents. So it earns its place.

The actor is Storm two six oh three, which is Microsoft's name for a group that has deployed Warlock ransomware, and LockBit before that. Kaspersky attributes this intrusion to it with moderate confidence, based on how it exploited SharePoint and what it did afterwards, both of which match other documented cases.

The way in was ToolShell, the pair of SharePoint flaws from the summer of twenty twenty five. A group with a working exploit for a famous vulnerability does not retire it because the vulnerability became famous. It keeps knocking until it finds a server nobody patched, or one that was patched but never cleaned.

Here is the sequence, and I would ask you to listen to the dates. On the twentieth of December there was a single probe against the ToolPane endpoint, apparently from a scanning service's infrastructure. About twelve minutes later, a connection arrived from a bulletproof hosting provider. Then nothing, for three days. On the twenty fourth of December, Christmas Eve, the full exploit chain ran against the w three w p process, the worker that serves SharePoint. A webshell was loaded straight into the A S P dot NET runtime. And the web server process launched the Windows installer to pull down a remote copy of Velociraptor. The intrusion was discovered on the twenty sixth. The probe on the twentieth had been seen, and triaged as low priority.

I mention the holiday because criminals read calendars too. A quiet probe, a three day pause, and then the real work on the one evening of the year when the security team is least likely to be watching. The low priority alert was correct, in a narrow sense. It was only a probe. It was also the only warning anyone was going to get.

Now, what the attacker brought, because it tells you how to hunt. The main implant is a C sharp framework Kaspersky calls vskp two. It exists only in memory, inside the SharePoint worker process. Patching the server afterwards does not remove it, and hunting only for files and hashes will miss it.

Then the attacker turned to legitimate software, as attackers increasingly do. Velociraptor, which is a respected digital forensics and incident response tool, here used as a remote control. And the version used was itself vulnerable to an older flaw, so the attacker installed a defender's tool with its own hole in it. Zoho Assist for unattended remote access. Visual Studio Code's command line tunnels, in both the regular and Insiders builds. And Cloudflare Tunnel.

Finally, the attempt to finish the job. The attacker loaded a vulnerable driver, named rsndispot dot sys, to switch off endpoint protection, alongside a sideloaded Warlock component built to kill antivirus software. Then it tried to deploy Warlock ransomware. Kaspersky's product blocked it. That is the happy ending, and it depended on the endpoint protection surviving the attempt to kill it.

So what do we do with this? Kaspersky's guidance falls into four parts.

First, look for the exploitation itself. In memory on SharePoint servers, that means the ToolPane related assemblies loading alongside Microsoft's generated code, and strings associated with dot NET deserialization attacks, the ones named ObjectDataProvider, ExpandedWrapper and LosFormatter.

Second, look for the implant hiding in the web application. Specifically, I I S configuration events that map a virtual path to a physical location that does not exist, without the file change events you would normally expect to see alongside them.

Third, behaviour. The SharePoint worker process launching the Windows installer. New outbound connections from SharePoint servers, which should be rare. Velociraptor, Zoho Assist, cloudflared or Visual Studio Code tunnels appearing on a host shortly after the web application was touched. And that driver loading.

Fourth, response. Contain at the host level. Rotate credentials, and rotate the SharePoint machine keys, because a stolen machine key lets an attacker come back even after the server is patched. Preserve memory and I I S telemetry before you rebuild, because the implant lives in memory and will be gone when you reboot. And correlate low signal reconnaissance with later privileged activity, which is the lesson of the twentieth of December.

I will add one thing of my own, and the brief marks it as mine rather than Kaspersky's. It is worth looking back through proxy and D N S logs for installer packages pulled by SharePoint servers from free hosting services, such as Cloudflare Workers, Supabase storage or catbox.

The indicators, including file hashes and the attacker's addresses, are in the written brief, as Kaspersky published them.

The broader point is this. We spend a great deal of time on the newest vulnerability of the week, and rightly so. But the attacker in this story used a flaw more than a year old, tools your own team might install, and a probe that everyone saw and nobody worried about. If your firm still runs SharePoint on its own servers, the question is not whether you patched ToolShell. It is whether anyone checked what was living in memory before you did.
