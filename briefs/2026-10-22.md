## 1. Top three things to know

1. **Microsoft names the ConnectWise attacker: China-aligned Storm-0940, driving an AI agent framework.**
   - Microsoft attributes the ConnectWise Cloud Backup compromise to **Storm-0940**, a China state-aligned actor active since at least 2021 and previously linked to the Quad7 password-spray botnet.

   - **Action:** keep ConnectWise / SkyKick apps disabled until ConnectWise issues instructions. Hunt for secrets added to *other* apps since 13 Oct, because those survive disabling the ConnectWise app. Deep dive in section 12.

   - Silent Ransom Group adds **Porter Hedges** (Houston law) plus another redacted listing.
   - **Action:** check advisers, auditors and outside counsel against these names.
3. **AI developer tooling compromised, PHP2Shell under attack, and a perfect-ten GitLab bug.**

## 5. Software supply chain

### LiteLLM 1.107.0: PyPI and Docker images backdoored
- **What:** LiteLLM is an open-source gateway for calling many AI models through one interface (about 23M weekly downloads). Version 1.107.0 shipped to PyPI and to GHCR/Docker Hub with the "privcollect" credential stealer and a backdoor. The `latest`, `main-latest` and `main-stable` Docker tags pointed at the bad image.
- **How:** stolen GitHub CLI OAuth tokens for three BerriAI engineers were used to push ten commits and run the release workflow. How the tokens were stolen is unknown.
- **Timeline (21 Oct, UTC):** commits 08:56–10:46; PyPI upload 11:39–11:40; Docker push 11:48; reported 12:06; removed from PyPI by 13:23; images removed 14:32.
- **Payload:** a `cook.pth` file runs at Python start-up and steals cloud tokens, SSH keys, AI tool credentials, browser data, environment variables, and LiteLLM proxy keys and model config. An hourly loader fetches further code.
- **Attribution:** none. Same start-up technique as the March 2026 LiteLLM compromise linked to TeamPCP (technique overlap only).
- **Fix:** pin 1.106.2 by digest, purge mirrors and caches, rotate every provider key plus the proxy master and salt keys, block litellm[.]dev.
- **IOCs:**

## 12. Threat actor deep dive: Storm-0940, ARTEX and the ConnectWise compromise

### Summary
- Microsoft attributes the ConnectWise Cloud Backup (SkyKick) multi-tenant app compromise to **Storm-0940**: China state-aligned, active since at least 2021, and previously linked to the Quad7 / CovertNetwork-1658 password-spray botnet.
- Since September 2026 it has used **ARTEX** to automate scanning, password spraying and OAuth app abuse against hundreds of organisations across aerospace and defence, energy, financial services, government, legal, think tanks and semiconductors. Sign-ins were attempted against **more than 2,250 tenants**.
- **ARTEX:** an open-source multi-agent LLM penetration-testing framework (Go, with a Next.js interface) that works with any model. Its developer, "Autumn-27", made it closed-source after CrowdStrike tied it to data theft from South Korean banks (8 Oct). Several actors use it.
- In some cases, privileged cloud access came **less than three hours** after initial targeting.

### Timeline (2026, UTC)
- **Sep:** ARTEX use begins.
- **10–14 Oct:** spray from 144.172.64[.]99 against 327 accounts at 8 organisations: more than 151,000 failures, peaking at 2,900 a minute. No successes.
- **13–14 Oct:** spray from 144.172.64[.]128 against four law-firm tenants (Huntress).
- **15 Oct:**
  - From 01:58: ConnectWise Cloud Management service principals give themselves directory roles, mostly Exchange Administrator, in about 50 tenants.
  - 03:44–03:49: the MS Teams app makes itself Global Administrator, then a Python script adds client secrets (expiring 2028) to an MSP management app and the Huntress app.
  - 06:13–08:44: tokens obtained across tenants from 144.172.64[.]128, in sorted GUID order.
  - 09:25–12:35: targeted sweep of 16 tenants in policy, national security, trade and critical minerals.
  - 13:54–14:20: an apparently manual second sweep across Exchange, SharePoint, Teams, Azure Resource Manager and Entra.
- **16 Oct:** ConnectWise advisory; Huntress confirms 162 tenants with unauthorised sign-ins.
- **17 Oct:** apps disabled; Cloud Backup, SaaS Security and Cloud Management suspended.
- **20 Oct:** credential reset complete.
- **21 Oct:** Microsoft publishes attribution; ConnectWise begins phased restoration.

### Access and tooling
- The vendor's client-assertion credential was used to get app-only Microsoft Graph tokens (T1195 supply chain compromise; T1078.004 valid cloud accounts), alongside password spraying of Microsoft 365.
- ARTEX agents run continuously and try parallel paths: reconnaissance, scanning, spraying and OAuth abuse.
- Python scripts and curl; Graph enumeration of directory, permissions, mail and SharePoint; Teams messages accessed through an email client.

### Persistence
- Service principals giving themselves Global Administrator or Exchange Administrator (T1098.003).
- **Client secrets or certificates added to other OAuth apps**, including MSP and security tools (T1098.001). These **survive disabling the ConnectWise app.**

### IOCs
- **IPs:** 144.172.64[.]128 (primary; AS14956 RouterHosting), 144.172.64[.]99 (spray 10–14 Oct), 144.172.64[.]60 (failed logins 18 Oct), 144.172.94[.]243 (broad spray, Huntress); VPN addresses on 15–16 Oct: 187.15.88[.]186, 187.15.90[.]217, 187.15.89[.]186.

- No domains or file hashes published for Storm-0940.

### Hunting
1. Find the apps **by app ID, not display name**, across all tenants, including unused integrations.
2. Service-principal sign-ins for those app IDs from 1 Oct, focusing on 15–16 Oct; flag non-Microsoft IPs, especially 144.172.64.0/24 and 187.15.88–90.x.
3. Graph activity logs for those app IDs. Zero results do not prove no access: directory reads leave no audit record.
4. Entra audit: a service principal adding itself to a role; "Add service principal credentials"; new apps, owners, consent grants and Conditional Access changes since 13 Oct; User-Agent Python-urllib/3.12.
5. Inventory every secret and certificate on app registrations, especially MSP, backup and security tools, added since 13 Oct. Flag secrets expiring in 2028.
6. Purview: mail access by OAuth apps after a role grant, SharePoint enumeration, inbox or forwarding rules, delegated mailbox permissions.
7. Defender alert titles: "Application self-assigned Global Administrator role"; "Unusual Microsoft Graph activity associated with Compromised ConnectWise Application"; "Suspicious addition of application role assignments by service principal to itself"; "Suspicious mail access activity by OAuth application following role assignment".
8. ARTEX spraying is very fast: alert on bursts of smart-lockout (50053) events from hosting providers.

### Response
- Disable affected apps but **do not delete them** (deletion destroys consent records and evidence). Keep them disabled until ConnectWise gives formal instructions.
- Preserve Entra, Purview and Graph logs, without delaying containment.
- Remove unauthorised secrets, certificates, role assignments, grants and owners; rotate credentials for affected apps.
- Harden: app management policies to restrict and shorten client secrets; minimise Application Administrator roles; Conditional Access for workload identities; review third-party apps holding Directory.ReadWrite.All, RoleManagement.ReadWrite.Directory or app-only Mail.Read.
- Ask MSPs and backup or SaaS vendors whether they use ConnectWise Cloud Backup, SaaS Security or Cloud Management, and whether their own tenants were reviewed.
